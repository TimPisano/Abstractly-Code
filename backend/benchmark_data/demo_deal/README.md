# Demo Deal: Maple Ridge Apartments

A fully fictional 120-unit multifamily acquisition package for sales demos of
the **Deal Mismatch Report**. No real property, owner, tenant, or lender is
represented anywhere in this package — every name, address, and dollar figure
below was invented for this demo.

- **Property:** Maple Ridge Apartments
- **Address:** 4500 Maple Ridge Trail, Dallas, TX 75248
- **Owner entity:** Maple Ridge Apartments Owner, LLC
- **Management company:** Cordant Residential Management, LLC
- **Units:** 120 (12 studio / 48 one-bedroom / 48 two-bedroom / 12 three-bedroom)
- **Rent roll as-of date:** 08/31/2026

Every file here is generated by `generate_demo_deal.py` in this directory
from one set of unit-inventory dictionaries — the lease PDFs, both rent-roll
CSVs, the T-12, and `expected_findings.json` are all computed from the same
source data, so they cannot silently drift out of sync with each other. Re-run
it any time with `venv/bin/python benchmark_data/demo_deal/generate_demo_deal.py`
from `backend/`.

## Files

```
leases/                                              15 sample lease PDFs
rent_roll/maple_ridge_rent_roll_120unit_appfolio.csv  full 120-unit rent roll
rent_roll/maple_ridge_rent_roll_demo_subset_16unit_appfolio.csv  16-unit extract (see below)
t12/maple_ridge_t12.xlsx                             12-month T-12 operating statement
expected_findings.json                               machine-readable ground truth for every planted issue
generate_demo_deal.py                                the generator (source of truth for everything above)
```

## Why there are two rent-roll files, and how to run the demo

This package includes 15 sample lease PDFs, not 120 — that's what was asked
for, and it keeps the package a manageable size. But the full 120-unit rent
roll has 120 units on it. If you upload the full 120-unit rent roll together
with only these 15 leases, the Deal Mismatch Report will correctly report
**~104 additional `unit_no_lease` findings** for every background unit that
simply doesn't have a sample lease PDF in this package — that's not a bug and
not one of the 10 issues planted below, it's just an artifact of shipping a
15-lease sample against a 120-row rent roll. Don't confuse that flood with the
one deliberately-planted `unit_no_lease` finding at unit F203.

Two ways to run a clean demo:

1. **Headline reconciliation demo (recommended):** upload
   `rent_roll/maple_ridge_rent_roll_demo_subset_16unit_appfolio.csv` (the
   same AppFolio-style format, filtered to just the 16 documented units)
   together with all 15 lease PDFs in `leases/`. The Deal Mismatch Report
   will show **exactly** the 10 planted issues below and nothing else.
2. **Scale demo:** separately show off
   `rent_roll/maple_ridge_rent_roll_120unit_appfolio.csv` on its own (parsing,
   rent roll dashboard, portfolio stats) to demonstrate Abstractly handling a
   realistic full-size PMS export. Don't run the Deal Mismatch Report against
   it together with only the 15 sample leases unless you want to also explain
   the 104 extra `unit_no_lease` rows.

**When importing either rent roll CSV**, set the uploader's base property
address to exactly `4500 Maple Ridge Trail, Dallas, TX 75248` — the "Unit"
column (e.g. `G204`) is a bare identifier with no "Suite"/"Unit" prefix, which
makes the app's rent-roll importer build each row's address as
`4500 Maple Ridge Trail, Dallas, TX 75248, Suite G204`. Every lease PDF's
stated property address was deliberately written to match that exact string
(see `generate_demo_deal.py`'s `_lease_paragraphs`) — if the base address is
typed differently, address matching will fail silently and none of the
matched-pair findings below will fire.

- **$45,355.00/year** in income overstatement across the 9 units where the
  app can assign a direction (4 rent mismatches + 2 expired-but-occupied + 3
  concessions, the last of which isn't live yet — see above).
- **+ $20,520.00/year** unconfirmed at the 1 no-lease unit (F203).
- **= $65,875.00/year total dollar exposure** across all 10 planted issues.

### 6 clean negative controls (deliberately no issue)

## T-12: collections ~6% below what the rent roll implies

`t12/maple_ridge_t12.xlsx` covers September 2025 through August 2026. Two
lines matter for this story:

- **Net Rental Income Billed: $2,044,072.64/year** — this is what the current
  rent roll's in-place rent, extended across the trailing year, implies the
  property should be collecting (Gross Potential Rent, less vacancy loss,
  less loss-to-lease).
- **Bad Debt / Collection Loss: $122,562.00/year**, i.e. **6.0%** of that
  billed amount — a chronic delinquency/write-off pattern that's real in the
  trailing financials but invisible if you underwrite off the rent roll alone.
- **Total Rent Collected: $1,910,310.64/year** — what actually came in.

A buyer underwriting purely off the rent roll's in-place rent (as the 4
rent-mismatch and 2 expired-but-occupied units above already show can't be
taken at face value) would also be missing that ~6% of billed rent
historically never converts to cash. NOI for the trailing year, after other
income and operating expenses, comes out to **$1,229,888.08**.

The Deal Mismatch Report itself only reconciles the rent roll against lease
PDFs — it doesn't ingest a T-12. The bad-debt story is meant for the
narrative half of the demo (SummaryMemo/InvestmentMemo/manual review), not
something to expect the Deal Mismatch Report to flag on its own.

## Regenerating

```
cd backend
venv/bin/python benchmark_data/demo_deal/generate_demo_deal.py
```

Fully deterministic (seeded RNG) — re-running produces byte-identical dollar
figures every time. Edit `DOCUMENTED_UNITS` / `NO_LEASE_UNIT` in
`generate_demo_deal.py` to change a planted issue; every downstream file
(leases, both rent rolls, the T-12's scheduled-rent baseline, and
`expected_findings.json`) is derived from those dicts, so there's exactly one
place to edit.
